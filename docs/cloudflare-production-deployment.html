Production Deployment

Operating procedure for the cloud-mail Worker at mail.edmf.nl, including the JWT signing secret used by every authenticated session.

JWT Secret

jwt_secret is an encrypted Cloudflare Worker secret, exposed at runtime as env.jwt_secret. It signs and verifies every login JWT.

Worker
cloud-mail
Binding
jwt_secret
Cloudflare type
secret_text
Public host
mail.edmf.nl
  • Cloudflare stores the value encrypted and never displays it after upload.
  • The secret belongs to the Worker, not the machine running Wrangler.
  • A normal deployment preserves encrypted Worker secrets.
  • Never add the value to wrangler.production.toml, .env, shell history, or Git.

Check that the binding exists without exposing its value:

cd ~/projects/cloud-mail/mail-worker
npx wrangler secret list --config wrangler.production.toml

The output must include jwt_secret with type secret_text.

Create or Rotate the Secret

Session impact: changing jwt_secret immediately invalidates all active browser sessions. Users must sign in again.

  1. Generate a new value, then save the displayed value in the password manager before continuing.
openssl rand -hex 48
  1. Upload that exact value interactively. This avoids accidentally uploading an empty secret through a shell pipeline.
npx wrangler secret put jwt_secret --config wrangler.production.toml
  1. Paste the generated value at Wrangler's prompt.
  2. Verify its name appears in wrangler secret list.
  3. Use a fresh browser session to test sign-in.

No extra deploy is required for a secret-only change. wrangler secret put publishes the updated Worker version itself.

Deployment Procedure

  1. Authenticate Wrangler to the Cloudflare account that owns cloud-mail. Use wrangler login or an appropriately scoped CLOUDFLARE_API_TOKEN.
  2. Confirm jwt_secret is listed as a Worker secret.
  3. Build and inspect the production package without publishing it.
npx wrangler deploy --dry-run --config wrangler.production.toml
  1. Deploy the Worker and frontend assets.
npx wrangler deploy --config wrangler.production.toml
  1. Hard-refresh mail.edmf.nl and test sign-in.
  2. For mail-related changes, send a controlled message and confirm the expected mailbox record is created.

Configuration differences: before accepting Wrangler's remote-configuration prompt, verify the local production file declares the intended D1, KV, R2, AI, assets, cron, variables, and custom-domain configuration. Continuing replaces the remote configuration with the local version.

Empty HMAC Key Recovery

The following error means the active Worker received an empty jwt_secret value:

Imported HMAC key length (0) must be a non-zero value
  1. Run wrangler secret list --config wrangler.production.toml.
  2. If jwt_secret is absent, create it using the interactive procedure above.
  3. If the name is present but the error persists, rotate it interactively. A secret binding can exist with an empty value.
  4. Wait briefly for the published version, hard-refresh the site, and sign in again.
  5. Confirm in the Cloudflare dashboard that mail.edmf.nl maps to the cloud-mail production Worker.

Cloudflare cannot recover a previously uploaded secret value. If the value was not saved when it was created, rotate it and store the replacement in the password manager.
